# ТЗ: image-to-vector

Локальный (100% клиентский) векторизатор растра в SVG с живым сравнением и
батч-обработкой. Ядро трассировки — готовое (VTracer, MIT). Ценность продукта —
в пре/пост-обработке, пресетах и мгновенной визуальной обратной связи.

---

## 0. Зачем это вообще

Движок векторизации писать не нужно: VTracer (Rust, MIT/Apache-2.0) уже даёт
контуры уровня платных сервисов. Но сам по себе он неудобен:

- параметры подбираются вслепую, методом тыка, без сравнения с оригиналом;
- полупрозрачные края PNG дают «бахрому» и цветной ореол по контуру;
- на выходе — мусорные узлы, десятки почти одинаковых цветов, раздутый SVG;
- нет батча с одинаковыми настройками;
- нет пресетов под типовые случаи (лого / штрих / постер / пиксель-арт).

Проект закрывает ровно эти пять пунктов. Трассировка — чужая, всё вокруг — своё.

**Anti-scope (явно НЕ делаем):** свой алгоритм трассировки, кластеризацию цветов
с нуля, аппроксимацию Безье с нуля, ML/диффузионную векторизацию, бэкенд,
аккаунты, оплату.

## 1. Задача №0 для исполнителя: верификация зависимостей

**Сделать это ДО написания кода и отчитаться результатом.** Спецификация ниже
предполагает браузерный WASM. Если предположение не подтвердится — архитектура
меняется (см. план Б).

Проверить:

1. `@visioncortex/vtracer` (npm, `1.0.0-alpha.3`, MIT OR Apache-2.0, ~690 KB,
   из `visioncortex/vtracer`, каталог `nodejs`). Ключевой вопрос: **работает ли
   сборка в браузере или она Node-only** (проверить наличие `fs`/`path` в
   бандле, тип WASM-загрузчика, наличие ESM-точки входа). Пакет в статусе alpha —
   зафиксировать точную версию.
2. Если браузерная сборка непригодна — оценить альтернативы:
   `wasm_vtracer`, `vtracer-wasm`, `vectortracer`, либо собрать самим
   `wasm-pack build --target web` из крейта `vtracer`.
3. Какие параметры реально экспортирует биндинг (полный список и типы).
4. Размер WASM после gzip/brotli, время холодной загрузки.

**План Б,** если браузерная сборка не выходит: Node-CLI + локальный сервер на
`@neplex/vectorizer` или `@visioncortex/vtracer`, UI тот же, но ходит на
`localhost`. Приватность сохраняется, «zero-install в браузере» теряется.

## 2. Архитектура

```
Файл(ы) ──► Preprocess (Canvas/WebGL) ──► Trace (VTracer WASM, Web Worker)
                                                      │
                       Compare/diff  ◄─── Postprocess (SVGO + свои проходы)
                                                      │
                                            Export: .svg / .zip
```

- Всё в браузере. Ни один байт изображения не уходит в сеть.
- Трассировка и постобработка — в Web Worker, UI не морозится.
- Состояние параметров — единый сериализуемый объект `Profile` (см. §6),
  один и тот же для UI, батча и CLI.

## 3. Пайплайн

### 3.1 Preprocess (наша реализация, Canvas 2D)

Каждый шаг отключаемый, порядок фиксированный:

1. **Alpha threshold** — пиксели с `a < T` → полностью прозрачные (`T` 0–255,
   по умолчанию 128). Убирает мусор в полупрозрачной кайме.
2. **De-fringe / unpremultiply** — устранение цветного ореола по краю
   прозрачного PNG: для пикселей с `0 < a < 255` восстановить цвет из соседних
   непрозрачных (расширение цвета наружу, «alpha bleed»), затем бинаризовать альфу.
   *Это главная боль исходной задачи — реализовать аккуратно и покрыть тестом.*
3. **Upscale ×2 / ×4** (nearest либо bilinear) — на мелких иконках заметно
   улучшает гладкость контуров. Для пиксель-арта только nearest.
4. **Despeckle** — удаление связных областей меньше N пикселей.
5. **Quantize** — сокращение палитры до K цветов (median-cut или k-means в
   Lab). Даёт предсказуемое число слоёв на выходе.
6. **Background removal** (для непрозрачных JPG/PNG): заливка от угловых
   пикселей с допуском по ΔE → альфа.

Вход: PNG/JPG/WebP/GIF(1 кадр)/BMP. Ограничение по стороне — 8192 px, при
превышении предупреждение и опция даунскейла.

### 3.2 Trace (VTracer)

Прокинуть в UI все параметры биндинга; как минимум:
`colormode` (color|binary), `hierarchical` (stacked|cutout), `mode`
(spline|polygon|pixel), `filter_speckle`, `color_precision`, `layer_difference`,
`corner_threshold`, `length_threshold`, `splice_threshold`, `path_precision`.
Точный список — по результату задачи №0.

### 3.3 Postprocess (наша реализация)

1. **Слияние близких цветов** — объединить заливки с ΔE(CIE76 или лучше) < порога
   в одну; порог в UI. Убирает «10 оттенков одного чёрного».
2. **Привязка к палитре** — пользователь задаёт список HEX (или подгружает из
   файла), все заливки снапятся к ближайшему цвету палитры. Для фирменного стиля.
3. **Упрощение путей** — Ramer–Douglas–Peucker по контрольным точкам с
   настраиваемым допуском (в % от диагонали), с гарантией: не увеличивать
   визуальную ошибку выше заданного порога.
4. **Регуляризация фигур** (опционально, off по умолчанию) — путь, близкий к
   окружности / прямоугольнику / прямой в пределах допуска, заменяется на
   идеальный примитив.
5. **SVGO 4.x** (MIT) — финальная минификация, округление координат до
   `path_precision`, удаление метаданных.
6. **Отчёт**: число путей, число узлов, число уникальных цветов, размер до/после
   каждого шага.

## 4. UI

Одна страница, три зоны.

**Зона просмотра** (главное — ради этого проект и делается):

- Режимы: `Оригинал` / `SVG` / `Шторка` (вертикальный слайдер-разделитель) /
  `Diff` (наложение с XOR-подсветкой расхождений) / `Узлы` (SVG + точки узлов).
- Общий зум и пан для всех режимов, зум до 1600%, «вписать», «100%».
- Шахматный фон под прозрачностью.
- Хоткеи: `1..5` — режимы, `Space` — зажать для показа оригинала, `F` — вписать.

**Панель параметров** — три группы (Pre / Trace / Post), каждая сворачивается.
Каждый слайдер: числовой ввод рядом, кнопка сброса, tooltip «что делает».
Дебаунс 150 мс, пересчёт автоматический; при тяжёлом изображении — кнопка
«Применить» вместо авто (переключатель).

**Статус-бар**: узлов, путей, цветов, размер SVG, время трассировки.

**Требования:** тёмная и светлая темы, адаптив от 1024 px, состояние
восстанавливается из `localStorage` (обёрнуто в try/catch), drag-n-drop файлов
на любую точку окна, вставка из буфера (`Ctrl+V`).

## 5. Пресеты

Встроенные, редактируемые, сохраняемые пользователем:

| Пресет | Назначение | Опорные настройки |
|---|---|---|
| `logo-flat` | лого, плоские иконки, прозрачный PNG | alpha threshold + de-fringe, quantize K=8, spline, stacked, слияние цветов агрессивное |
| `lineart` | штрих, скан, чертёж | binary, despeckle, spline, упрощение путей |
| `poster` | фото → постеризованный вектор | quantize K=6..16, stacked, высокий filter_speckle |
| `pixel-art` | пиксель-арт 1:1 | без upscale-сглаживания, `mode=pixel`, без упрощения |
| `max-fidelity` | точность важнее размера | минимум упрощения, высокий color_precision |

Пользовательский пресет = сериализованный `Profile`, экспорт/импорт `.json`.

## 6. Профиль, батч и CLI

**`Profile`** — единый JSON-объект: `{version, preprocess:{...}, trace:{...},
postprocess:{...}}`. Всё, что влияет на результат, лежит только здесь.

**Батч:** перетащить N файлов → применить один `Profile` ко всем → прогресс по
файлам → скачать `.zip` (JSZip) + `report.csv` (имя, узлы, цвета, размер).
Обработка последовательная, с возможностью отмены.

**CLI** (`packages/cli`, Node): `image-to-vector in/*.png -o out/ --profile logo-flat.json`.
Использует **тот же** код пре/постобработки, что и веб (общий пакет `core`),
трассировку — через Node-биндинг. Одинаковый `Profile` обязан давать одинаковый
SVG в вебе и в CLI — это покрывается тестом.

## 7. Стек и репозиторий

- TypeScript, strict.

  (VTracer MIT/Apache-2.0, SVGO MIT). **Potrace (GPL) не тянуть** — заразная
  лицензия, для MIT-проекта неприемлемо.

## 8. Этапы

| Этап | Содержание | Критерий готовности |
|---|---|---|
| **M0** | Задача №0 (§1) | письменный отчёт: какой пакет, какие параметры, размер, браузер/Node |
| **M1** | Скелет монорепо, загрузка файла, трассировка в воркере, сырой вывод SVG, скачивание | PNG с прозрачностью превращается в SVG в браузере, без сети |

## 9. Критерии приёмки

1. Прозрачный PNG-логотип 512×512 → SVG **без цветной бахромы по контуру**
   (визуальная проверка на зуме 800% против исходника).
2. Число уникальных цветов в выходном SVG равно заданному K после слияния,
   а не K+30 почти-дублей.
3. Размер SVG после постобработки меньше сырого вывода VTracer минимум на 30%
   при сохранении визуального сходства (diff-режим не показывает заметных
   расхождений).
4. Ни одного сетевого запроса с данными изображения — проверяется вкладкой
   Network при полном прогоне.
5. Батч из 50 иконок отрабатывает без утечки памяти (вкладка Memory: heap
   возвращается к базовому уровню после сборки мусора).
6. `npm test` и `npm run build` зелёные, страница задеплоена.
